# 4. Permissions et limites

Le modèle de permissions détermine qui peut créer, modifier, exécuter, annuler ou retirer les fonds d’une tâche. Les rôles du contrat et ceux du service d’exécution ne doivent pas être confondus.

Les principaux risques sont l’appel d’une mauvaise cible, la surconsommation de gas, la condition de resolver obsolète et le financement insuffisant.

Les adresses déployées, les paramètres de réseau et les versions de contrats doivent être vérifiés séparément du code source. Une tâche correctement signée n’est pas automatiquement sûre si sa cible est mal configurée.

Dernier chapitre : les tests et la documentation amont servent de références pour approfondir, mais aucun test ni déploiement n’a été exécuté dans ce parcours documentaire.
